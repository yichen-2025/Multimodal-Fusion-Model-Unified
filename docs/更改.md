# IoT Network Intrusion Dataset 迁移说明

本文档记录了项目从原始数据集（Friday-WorkingHours-Afternoon-DDos）迁移到新数据集（IoT Network Intrusion Dataset）的所有改动。

## 一、数据集对比

### 1.1 原始数据集

| 属性 | 值 |
|------|-----|
| 文件名 | `Friday-WorkingHours-Afternoon-DDos.pcap_ISCX.csv` |
| 标签列 | `Label` |
| 标签值 | `BENIGN`（正常流量）、`DDoS`（恶意流量） |
| 特征列数 | 78 |
| 样本量 | ~20万行 |

### 1.2 新数据集

| 属性 | 值 |
|------|-----|
| 文件名 | `IoT Network Intrusion Dataset.csv` |
| 标签列 | `Label` |
| 标签值 | `Normal`（正常流量）、`Anomaly`（恶意流量） |
| 特征列数 | 83 |
| 样本量 | ~26万行（260MB+） |

## 二、特征选择变更

### 2.1 统计特征模态（9个连续特征）

**旧版（Friday-WorkingHours-Afternoon-DDos）**：

| 序号 | 特征列名 | 含义 |
|------|---------|------|
| 1 | `Destination Port` | 目标端口 |
| 2 | `Bwd Packet Length Mean` | 反向包平均长度 |
| 3 | `Avg Bwd Segment Size` | 反向段平均大小 |
| 4 | `Bwd Packet Length Max` | 反向包最大长度 |
| 5 | `Bwd Packet Length Std` | 反向包长度标准差 |
| 6 | `URG Flag Count` | URG标志计数 |
| 7 | `Packet Length Mean` | 包平均长度 |
| 8 | `Average Packet Size` | 平均包大小 |
| 9 | `Packet Length Std` | 包长度标准差 |

**新版（IoT Network Intrusion Dataset）**：

| 序号 | 特征列名 | 含义 |
|------|---------|------|
| 1 | `Flow_Duration` | 流持续时间 |
| 2 | `Tot_Fwd_Pkts` | 前向包数量 |
| 3 | `Tot_Bwd_Pkts` | 反向包数量 |
| 4 | `TotLen_Fwd_Pkts` | 前向包总长度 |
| 5 | `TotLen_Bwd_Pkts` | 反向包总长度 |
| 6 | `Flow_Byts/s` | 流字节速率 |
| 7 | `Fwd_Pkt_Len_Mean` | 前向包平均长度 |
| 8 | `Bwd_Pkt_Len_Mean` | 反向包平均长度 |
| 9 | `Pkt_Len_Mean` | 包平均长度 |

**选择理由**：新数据集的特征命名采用Snort/Zeek网络流量分析标准，包含更丰富的流级别统计信息。所选9个特征覆盖了时间维度（流持续时间）、数量维度（包数量）、长度维度（包总长度/平均长度）和速率维度（字节速率），能够全面刻画网络流量的统计特征。

### 2.2 文本描述模态（离散特征）

**旧版**：仅使用9个数值特征生成文本描述。

**新版**：除了9个数值特征外，额外引入以下离散字段作为文本描述的一部分：

| 字段 | 含义 | 示例 |
|------|------|------|
| `Protocol` | 协议类型 | TCP, UDP, ICMP |
| `Src_IP` | 源IP地址 | 192.168.0.13 |
| `Src_Port` | 源端口号 | 554 |
| `Dst_IP` | 目的IP地址 | 222.160.179.132 |
| `Dst_Port` | 目的端口号 | 2179 |

**文本描述生成示例**：

```
协议类型为TCP。源IP地址192.168.0.13。源端口号554。目的IP地址222.160.179.132。
目的端口号2179。流持续时间10.50秒。前向包数量25。反向包数量18。
流字节速率1234.56字节/秒。前向包平均长度256.78字节。
反向包平均长度312.45字节。平均包长度289.62字节。
```

## 三、标签编码变更

## 五、数据清洗脚本使用说明

### 5.1 指定数据集文件

```python
# 通过代码调用
from scripts.data_cleaning import main as run_data_cleaning
run_data_cleaning(dataset_filename="IoT Network Intrusion Dataset.csv")
```

```bash
# 通过命令行直接运行
python scripts/data_cleaning.py --dataset "IoT Network Intrusion Dataset.csv"
python scripts/data_cleaning.py -d "IoT Network Intrusion Dataset.csv"
```

### 5.2 不指定数据集（自动检测）

```python
# 将自动使用 data_processing/ 目录下的第一个CSV文件
run_data_cleaning()
```

### 5.3 错误处理

当指定的数据集文件不存在时，脚本会：
1. 打印错误信息，说明找不到的文件路径
2. 列出 `data_processing/` 目录中所有可用的CSV文件
3. 返回 `False`，终止运行

## 六、GPU检查机制

### 6.1 触发时机

在以下脚本执行GPU密集型操作前自动触发：

- `split_modality.py`：BERT文本嵌入提取前
- `train.py`：模型训练前
- `test_model.py`：模型测试前

### 6.2 检查逻辑

```python
if not torch.cuda.is_available():
    print("⚠️  WARNING: 未检测到可用的GPU设备！")
    # 提示用户选择：继续使用CPU(y) / 终止程序(N)
    choice = input("是否继续使用CPU运行？(y/N): ")
    if choice != 'y':
        exit(1)  # 终止程序
```

### 6.3 BERT编码器GPU优化

`BertEncoder` 新增以下优化：

| 优化项 | 说明 |
|--------|------|
| 自动GPU检测 | `__init__` 中自动检测 `torch.cuda.is_available()`，将模型 `.to('cuda')` |
| 分批推理 | `forward()` 新增 `batch_size` 参数（默认32），分批送入BERT后拼接 |
| 进度日志 | 每处理10%输出进度和耗时 |
| 设备信息 | 初始化时打印模型所在设备 |

## 七、运行步骤（新版）

```bash
# 步骤0：下载模型（首次运行）
python scripts/download_bert.py
python scripts/download_qwen.py

# 步骤1：数据清洗
python scripts/data_cleaning.py --dataset "IoT Network Intrusion Dataset.csv"

# 步骤2~6：通过 main.py 执行
python main.py
```

或通过 `main.py` 逐步取消注释执行。

## 八、注意事项

1. **数据集文件大小**：新数据集约260MB，建议使用分批处理以避免内存溢出。
2. **GPU显存**：BERT推理建议至少4GB显存，训练建议至少16GB显存。
3. **首次运行**：首次使用前请确认已下载BERT和Qwen模型到 `models/` 目录。
4. **标签一致性**：确保数据集的 `Label` 列值为 `Normal` 或 `Anomaly`，否则需要在 `data_cleaning.py` 中调整标签映射。
